## 旁白稿（可直接照读，约 700 字 / 4 分 30 秒）

> 学生最常问的两个问题——「我还差多少学分毕业」「这门课我现在能不能选」——答案不在任何一张表里。学分结构表只写模块要求，课程设置表只登记学分，先修要求表用的是"数据结构与算法或计算机组成原理之一""已完成专业核心课不少于 40 学分"这样的自然语言条件。学生自己翻 PDF 容易看漏，通用大模型会算错，而且说不清依据在哪一页。
>
> 「课径」把这件事重新定义为可核算的问题。整体分三层：最上面是 Dify 的工作流，负责理解问题、检索、分流和输出；中间是自研的外部知识服务，实现 Dify 的外部知识库契约；最下面是确定性的核算引擎，负责学分和先修的计算。核心原则只有一句：检索负责找依据，代码负责算结论，模型不参与算术。
>
> 第一问，先修。我修过 CS101 和 CS201，问编译原理能不能选。系统判定不满足，缺一门直接先修 CS202，并且给出依据来自培养方案第 14 页第 3 行，匹配度 1.00。这里没有让模型猜，先修条件被解析成表达式树，与、或、学分门槛分别求值。
>
> 第二问，学分。问毕业还差多少。系统回答已认定 8 学分、还差 152，并按四个模块逐项列出缺口。请注意一条容易误解的规则：模块超额不冲抵其他模块，剩余学分是各模块缺口之和，而不是总学分减已修学分——否则学生会按错误口径排课。
>
> 第三问，条款。转专业的学分怎么认定。这类问题不进入核算，直接返回知识库里最相关的原文条款，同样带页码和行号。
>
> 工程上有三个数字可以说明完成度：149 项自动化测试全部通过，不依赖平台和网络；检索在引入意图加权后，Recall@1 从 0.833 提升到 1.000；核算与先修评测共 17 个用例全部精确匹配。
>
> 所有成果以 Apache-2.0 开放：知识服务源码、工作流 DSL、部署脚本、评测集和文档。作品没有修改也没有 fork Dify 的任何源码，只使用了官方支持的外部知识库契约、HTTP 节点、代码节点和覆盖编排；依赖里刻意避开了 AGPL 组件，演示数据全部为合成样例，不含任何院校信息。
>
> 下一步会接入 OCR 把扫描版教学大纲纳入链路，并在意图识别层引入小模型、保留规则兜底。「课径」，让每一条回答都能被逐项核对。

## 十、自动化生成（已实现，非人工剪辑）

成片 `video/课径-演示视频.mp4` 由脚本生成，可完整复现：3 分 47 秒 / 1920×1080 / 30fps / H.264 + AAC / 9.7 MB。

```powershell
# 0. 一次性：建报告/视频工具环境（不需要 Dify，但录制需要 Dify 已启动）
& ".\tools\python\python.exe" -m venv .\.tools\rptvenv
.\.tools\rptvenv\Scripts\python.exe -m pip install markdown pypdf pypdfium2 pillow playwright imageio-ffmpeg

# 1. 静态画面（6 张 1920×1080）
.\.tools\rptvenv\Scripts\python.exe video\make_slides.py

# 2. 真实界面录屏（Playwright 驱动本机 Edge，登录 → 打开应用 → 三问）
.\.tools\rptvenv\Scripts\python.exe video\record_demo.py

# 3. 合成：旁白（Windows SAPI 中文音色）+ 变速对齐 + 拼接 + 封装
.\.tools\rptvenv\Scripts\python.exe video\build_video.py
```

**旁白说明**：当前旁白由 Windows 内置中文语音（Microsoft Huihui）合成，语气偏机械。若需真人配音，按本文件第七节的旁白稿重新录制，替换 `video/.build/voice/s*.wav` 后重跑第 3 步即可（时长会按新音频自动重算）。
