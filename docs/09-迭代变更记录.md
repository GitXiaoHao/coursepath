# 课径 · 迭代变更记录

## 2026-10-21 · 学生课程档案（第一阶段）

- 新增 SQLite 持久化学生课程档案：以 Dify 稳定用户标识为键，仅保存课程代码、学分与通过状态，不保留原始对话。
- `/audit` 与 `/prereq` 自动合并本轮明确输入与已保存档案；用户不必在后续提问重复填写课程。
- 新增档案接口：查看、合并课程、覆盖课程、删除单门课程、清空档案。
- 新增 `/profile-summary` 文本摘要接口，并在 Dify 对话中接入“我的档案 / 查看档案”分支。
- Compose 为档案数据库增加宿主机持久化挂载；服务重启不丢失记录。
- Dify 工作流传递 `sys.user_id` 至核算服务；先修回答以已合并档案后的确定性结果为准。

## 后续计划

1. 在 Dify 对话中增加“删除课程 / 清空档案”的二次确认交互入口。
2. 接入学号/统一认证并完善档案访问控制。

## 2026-10-21 · 修读规划（第二阶段）

- 新增 `/study-plan`：仅从培养方案已登记课程中筛选当前满足直接先修的未修课程。
- 按模块学分缺口、课程学分和课程代码排序，输出可解释的候选优先级。
- 明确排除开课学期、容量、时间冲突与教务限制，避免将候选建议误表述为正式选课结果。

## 2026-10-21 · 档案安全管理（第三阶段）

- 新增 `/profile-command`，支持通过对话发起单门课程删除与档案清空。
- 删除和清空均采用二次确认：先显示影响范围，只有收到“确认删除 课程代码”或“确认清空档案”才实际写入。
## 2026-10-21：可分发插件化（v0.2.0）

### 本次交付

- 将既有 Dify 插件从“课径核算”扩展为“课径学业助手”：保留 `credit_audit`（学分核算）与 `prereq_check`（先修判定），新增 `study_plan`（修读规划建议）。
- 插件内核随 `.difypkg` 一起分发，全部为本地确定性计算；安装者不需要配置 `campus-kb` 地址、Docker 私网白名单、API Key 或模型供应商即可使用基础能力。
- 修读规划只输出当前满足培养方案登记先修条件的候选课程，并按模块缺口与课程学分排序；明确标注它不包含开课学期、容量、时间冲突与教务限制。
- 重新生成安装包：`dify-plugin/dist/course_audit-0.2.0.difypkg`。
- 新增 `dify-workflow/build_plugin_demo.py` 的应用安装流程：安装插件后自动读取该实例的插件标识，生成并发布“课径插件演示 · 学业助手”。工作流按问题文本分流到学分核算、先修判定或修读规划，避免让使用者手工连接三个工具节点。
- 将插件模板的关键词分流替换为“千问意图识别 → 代码校验 → 工具分支”：模型只输出 `audit`、`prereq`、`study_plan` 标签，温度固定为 0；代码节点校验 JSON 并保留保守回退。课程事实和结论仍不由模型生成。
- 在同一校验节点加入本轮已修课程提取：仅合并用户明确写出“已修、修过、学过、已通过、修完”等完成状态时由模型返回、且实际出现在原问题中的规范课程代码；表单课程始终保留，并排除紧邻“能选、先修”等问法的目标课程代码。
- 每条工具分支后增加“千问润色”节点。该节点的唯一输入事实为插件返回的文本，提示词明确禁止新增、修改或省略课程、学分、先修、可选结论与教务规则；其职责仅为将结果改写成简洁自然的中文，并保留修读建议不能替代正式选课的限制。
- 以 `campus-kb/data/samples/plan.json` 作为培养方案单一来源。服务启动时从该结构化方案自动生成模块与课程目录分块并加入原有知识库索引：当前示范方案新增 5 个模块与 43 门课程目录，均保留页码、表格行与原文依据；检索不再只依赖少量概述条款。
- 新增 `dify-plugin/sync_plan.py`：同步同一份方案到插件的默认资产，配合 `sync_core.py` 避免插件、核算服务、检索依据三方规则漂移。插件版本提升至 `0.2.1`。
- 插件工作流生成器新增 `--with-knowledge`。在有 `campus-kb` 部署的完整模式下，它会复用或登记当前外部知识库，在插件工具回答后附上 Dify 检索到的页码/表格行依据；未启用该开关时，仍保留可离线分发的纯插件模式。

### 产品边界

- 内置培养方案仅为合成演示数据。真实院校使用前必须由部署方提供经过核验的 `plan_json` 或对应培养方案包。
- 跨会话的学生档案不能由便携插件“默认保存”。该能力继续作为可选的服务端适配层：必须先有身份认证和由部署方管理的数据库，才可启用。
- 因此发布形态分为两层：普通用户安装插件即可得到核算、先修、规划；有校园系统权限的部署方再接入档案、成绩和正式选课数据。
