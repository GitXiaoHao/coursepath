# 08 · 插件使用指南（别人拿到 `.difypkg` 后怎么跑）

面向拿到 `course_audit-0.1.1.difypkg` 的第三方：从安装到出结果，全程不联网、不需要 API Key、不需要本项目的服务器。

> 插件把核算内核（`schema` / `graph` / `scoring` 三个纯 Python 模块）**随包分发**，在 Dify 插件容器内本地执行。所以它不依赖 `campus-kb` 服务，也不发任何外网请求。

## 一、你会拿到什么

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `course_audit-0.1.1.difypkg` | 24.6 KB | Dify 工具插件包（21 个文件，无 `.env`、无缓存） |

仓库位置：`dify-plugin/dist/course_audit-0.1.1.difypkg`（仓库 <https://github.com/GitXiaoHao/coursepath>，该文件已入库，可直接下载）。

**前提**：一个能登录的 Dify，版本 ≥ 1.0.0（本作品在 1.17.1 上验证）。没有的话见仓库 `deploy/bootstrap.ps1`（本机 Docker 一键起 Dify）。

### 想自己从源码重打包

`.difypkg` 就是一个 zip（根目录放 `manifest.yaml`）。仓库提供了不依赖 `dify-plugin` 开发 CLI 的打包脚本：

```powershell
.\.tools\rptvenv\Scripts\python.exe dify-plugin\pack.py                         # 默认打 course-audit/ → dist/
.\.tools\rptvenv\Scripts\python.exe dify-plugin\pack.py --check                 # 只列清单不写产物
```

实测：用该脚本重打包出的包与官方 CLI 产物**文件清单逐项一致（21 项）**，上传后 Dify 侧日志出现 `Installed tool: course_audit` 与 `local runtime ready`，即包结构被接受、插件正常加载。

## 二、安装（4 步，界面路径按 Dify 1.17.1）

1. 左侧菜单点 **集成**；
2. 左上角 **安装** → 下拉里选 **本地集成包**（另外两项是 Marketplace / GitHub）；
3. 选择 `course_audit-0.1.1.difypkg`，等待右上角提示安装完成（约 10–30 秒，取决于是否要拉 Python 依赖）；
4. 回到 **集成** → 左侧二级菜单点 **工具**，能看到「**课径核算** / Course path audit」即成功。

### 如果报「签名校验失败」

自建的 `.difypkg` 没有官方签名，Dify 默认开启强制校验：

```
plugin verification has been enabled, and the plugin you want to install has a bad signature
```

在你自己的 Dify 部署目录（`deploy/dify/docker/.env`）改一行，然后重启三个容器：

```bash
# .env
FORCE_VERIFYING_SIGNATURE=false
```

```bash
docker compose up -d api worker plugin_daemon
```

这是**部署侧配置**，不是改 Dify 源码；从 Marketplace 安装的官方插件不需要这一步。

### 如果报 `Permission denied (os error 13)` / `failed to init environment`

Windows 上 Docker 的绑定挂载（9p/drvfs）不支持 uv 缓存的原子重命名。给 `plugin_daemon` 加环境变量：

```yaml
UV_CACHE_DIR: /tmp/uv-cache
HOME: /tmp
XDG_CACHE_HOME: /tmp/.cache
```

（本项目 `deploy/dify.override.yaml` 已经这样配了。）

## 三、跑起来（两条路径）

### 路径 A：在工作流里当工具节点用（推荐）

1. **工作室** → 创建空白应用 → 选 **Chatflow**（或 Workflow）；
2. 在画布上点 `+` → 选 **工具** 节点；
3. 工具列表里选 **课径核算** → 工具选 `credit_audit`（学分核算）或 `prereq_check`（先修检查）；
4. 填参数（两个工具都不需要凭据 / 授权配置）：

| 工具 | 参数 | 必填 | 填法 |
| --- | --- | --- | --- |
| `credit_audit` | `completed` | 是 | 已修课程，如 `CS101,CS201`；支持 `CS101:3、CS201`、`CS101(3)` 等写法（逗号、分号、中文逗号、顿号都行） |
| `credit_audit` | `plan_json` | 否 | 留空 = 用内置合成培养方案；填自己的方案见第四节 |
| `prereq_check` | `course` | 是 | 课程名或代码，如 `编译原理` 或 `CS305` |
| `prereq_check` | `completed` | 否 | 同上 |
| `prereq_check` | `plan_json` | 否 | 同上 |

5. 工具节点输出两个消息：**文本**（Markdown 摘要，可直接接到「回答」节点）和 **JSON**（结构化，供下游节点取字段）。

**期望输出（内置示例方案 + `completed=CS101,CS201`）**

`credit_audit`：

```
### 学分核算 · 示范专业（培养方案 1.0.0）
- 总学分 160，已认定 8，**还差 152 学分**
- 模块缺口：
  - 通识教育：已修 0/48，缺 48
  - 专业核心课：已修 8/56，缺 48
  - 专业选修课：已修 0/24，缺 24
  - 实践教学环节：已修 0/32，缺 32
- 依据规则：R1 只计已通过课程；R4 超额不冲抵；R5 剩余=各模块缺口之和
```

`prereq_check`（`course=编译原理`）：

```
### 先修检查 · 编译原理（CS305）
- 结论：**不满足**，缺 1 门直接先修
- 直接先修（必须先通过）：
  - 计算机组成原理（CS202）：尚未通过
- 需同时满足：已修 数据结构与算法（CS201）；缺少先修课程 计算机组成原理（CS202）
- 判定依据：先修关系来自培养方案/教学大纲登记，逐条可回溯，非模型生成
```

> 数字是确定性的：`CS101`(4 学分) + `CS201`(4 学分) 计入「专业核心课」→ 8/56，所以还差 152。换成你自己的 `completed` 会立刻变化，可用这个差值自检。

### 路径 B：不装 Dify，直接验内核

插件的三个核模块与 `campus-kb/` 里的完全同源（`dify-plugin/sync_core.py --check` 可校验 sha256 一致）。只想确认算法正确性时：

```powershell
cd campus-kb
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
.\.venv\Scripts\python.exe -m pytest -q      # 期望 149 passed
.\.venv\Scripts\python.exe -m eval.run_eval  # 期望退出码 0
```

评测口径：检索 Recall@1 = 1.000（基线 0.833）、核算 7/7、先修 10/10，详见 `docs/03-评测结果.md`。

## 四、换成自己的培养方案

`plan_json` 填一个 JSON 字符串。最小可用示例：

```json
{
  "plan_id": "my-plan-2026",
  "major": "某专业",
  "version": "1.0.0",
  "total_credits": 160,
  "modules": [
    { "module": "通识教育", "required": 48 },
    { "module": "专业核心课", "required": 56 }
  ],
  "courses": [
    {
      "code": "CS101",
      "name": "程序设计基础",
      "credits": 4,
      "module": "专业核心课",
      "terms": ["1"],
      "prerequisites": null
    },
    {
      "code": "CS305",
      "name": "编译原理",
      "credits": 3.5,
      "module": "专业核心课",
      "terms": ["5"],
      "prerequisites": {
        "kind": "and",
        "children": [
          { "kind": "course", "course_code": "CS201" },
          { "kind": "course", "course_code": "CS202" }
        ]
      }
    }
  ]
}
```

先修表达式支持四种节点：

| kind | 写法 | 含义 |
| --- | --- | --- |
| `course` | `{"kind":"course","course_code":"CS201"}` | 必须先通过某门课 |
| `and` | `{"kind":"and","children":[...]}` | 全部满足 |
| `or` | `{"kind":"or","children":[...]}` | 任一满足（不满足时给出阻塞项最少的分支） |
| `credits` | `{"kind":"credits","module":"专业核心课","min_credits":40}` | 某模块已修学分 ≥ N |

核算规则（结论里会标出规则号，便于核对）：

| 规则 | 含义 |
| --- | --- |
| R1 | 只计 `passed=true` 的课程 |
| R2 | 培养方案外的课程不认定，单独列为「未登记」 |
| R3 | 学分一律以方案登记值为准，学生上报不一致时告警 |
| R4 | 模块超额不冲抵其他模块缺口 |
| R5 | 剩余学分 = 各模块缺口之和，**不等于**「总学分 − 已修」 |

真实培养方案解析成上面的 JSON 需要表格抽取：`campus-kb/core/parser.py` 支持 Markdown 表格与 PDF（pdfplumber），命令见 `docs/05-系统集成说明.md`。

## 五、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 工具节点里找不到「课径核算」 | 安装后未刷新：重启 `plugin_daemon` 容器，或换页面重进 |
| 回答里出现 `credit_audit.body.summary` 这种字面量 | 取的是 JSON 字段而工具给的是文本消息：直接接「回答」节点取工具的 **text** 输出，不要拼 `body.xxx` |
| `completed` 传空 | 必填；只需给课程代码，学分由方案补全 |
| 课程名有歧义（如「数据结构」匹配到多门） | 用课程代码（`CS201`）代替名称 |
| 想核对某个数字怎么来的 | 文本输出末尾带规则号，JSON 输出里 `explain` 字段逐条给出依据 |

## 六、许可与数据边界

- 代码 Apache-2.0；内置 `plan-demo.json` 是**合成样例**（无任何真实院校信息），文档与样例数据 CC-BY-4.0。
- 插件不收集、不存储、不记录任何输入；无外网请求（详见包内 `PRIVACY.md`）。
- 真实培养方案/学号等敏感数据不要传给任何第三方环境。
