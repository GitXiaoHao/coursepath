# 07 工具插件：设计、打包与验证

> 目的：说明 `dify-plugin/course-audit` 这个 `.difypkg` 是什么、为什么这么设计、怎么打包与验证，以及踩过的坑。
> 定位：**开放成果加分项，不是晋级门禁**。主路径（Chatflow + 外部知识库 + 自研服务）不依赖它。

---

## 1. 设计取舍：为什么插件自带内核

插件有两种写法：

| 方案 | 做法 | 问题 |
| --- | --- | --- |
| A 包一层已有 API | 插件内部 HTTP 调 `campus-kb/audit` | 本质是"机械封装"，正是市场审核与赛题都明确排斥的形态；且插件离开本机服务就不可用 |
| B 内核随包分发（**采用**） | 把 `core/schema.py`、`core/graph.py`、`core/scoring.py` 三个**纯 Python、无第三方依赖**的模块复制进插件，插件内直接调用 | 需要在两处维护同一份逻辑，用同步测试 + 哈希比对约束 |

选 B 的三条理由：

1. **独立性**：插件装上就能算，不依赖任何外部服务/密钥，符合"开放成果可被他人直接复用"；
2. **可审核性**：没有网络出站，风险等级可判为 Low risk（只做本地确定性计算）；
3. **叙事一致**：报告主张"结论由确定性代码给出"，插件的实现与主张一致。

代价与对策：内核副本与 `campus-kb/core/` 必须保持一致。上一版做过逐字段等价测试；本版用 `_assets/` 里的示例方案 + 同步脚本手工对齐，并在 README 里写明"改内核需同步两处"。

## 2. 包结构

```
dify-plugin/course-audit/
├── manifest.yaml           # 插件元信息（type: plugin, runner python 3.12）
├── main.py                 # 入口：注册 provider
├── provider/
│   ├── course_audit.yaml   # 工具 provider 声明（identity/tools/extra）
│   └── course_audit.py     # class CourseAuditProvider(ToolProvider)
├── tools/
│   ├── audit.yaml          # credit_audit 的 identity/description/parameters
│   ├── audit.py            # class CourseAuditTool(Tool) → 调 core.scoring.audit_credits
│   ├── prereq.yaml         # prereq_check
│   ├── prereq.py           # 调 core.graph.check_prerequisites
│   └── _shared.py          # 载入随包示例方案、解析 "CS101,CS201" 文本
├── core/                   # 内核副本（schema/graph/scoring），无第三方依赖
├── _assets/                # icon.svg / icon-dark.svg / plan-demo.json
├── README.md               # 英文，含安装/配置/用法/凭据/源码链接
├── PRIVACY.md              # 声明不收集任何数据
└── requirements.txt        # 仅 dify-plugin（由 dify plugin init 生成）
```

**两个工具**

| 工具 | 参数 | 输出 |
| --- | --- | --- |
| `credit_audit` | `completed`（必填，课程代码文本）、`plan_json`（可选，缺省用随包示例） | 分模块学分缺口 + 规则编号 R1/R4/R5 |
| `prereq_check` | `course`（必填，名称或代码）、`completed`、`plan_json` | 是否满足先修、缺哪些直接/间接先修 |

## 3. 打包

开发者 CLI 来自 `langgenius/dify-plugin-daemon` 的发布二进制（**不是** PyPI 的 `dify_plugin` 包——后者只有运行时 CLI，没有 `dify plugin init/package` 子命令）。

```powershell
# 一次性：下载插件 CLI（Windows x86_64）
curl -L -o dify-plugin-cli.zip https://github.com/langgenius/dify-plugin-daemon/releases/download/0.6.11/dify-plugin-windows-amd64.zip
Expand-Archive dify-plugin-cli.zip -DestinationPath .tools/plugin -Force

# 每次打包
.\.tools\plugin\dify-plugin.exe plugin package .\dify-plugin\course-audit `
    -o .\dify-plugin\dist\course_audit-0.1.1.difypkg
```

产物约 **24.6 KB / 21 个条目**，不含 `__pycache__`、`.venv`、`.env`、密钥（已用 `.difyignore` 与文件清理双重保证）。

## 4. 安装到本机 Dify 并验证

```powershell
# 前提：Dify 已起来（deploy/bootstrap.ps1），且 .env 里 FORCE_VERIFYING_SIGNATURE=false
python deploy\install_plugin.py --pkg dify-plugin\dist\course_audit-0.1.1.difypkg
python dify-workflow\build_plugin_demo.py --import
```

`install_plugin.py` 走三个控制台接口：`plugin/upload/pkg`（解码出 `unique_identifier`）→ `plugin/install/pkg`（真正安装）→ 轮询 `plugin/list` 确认。

`build_plugin_demo.py` 生成并导入一个**只含三个节点**的工作流（`start → 插件工具 → answer`），发布后走服务 API 调用。实测输出（`PLUGIN TOOL PASS`）：

```
### 学分核算 · 示范专业（培养方案 1.0.0）
- 总学分 160，已认定 8，**还差 152 学分**
- 模块缺口：
  - 通识教育：已修 0/48，缺 48
  - 专业核心课：已修 8/56，缺 48
  - 专业选修课：已修 0/24，缺 24
  - 实践教学环节：已修 0/32，缺 32
- 依据规则：R1 只计已通过课程；R4 超额不冲抵；R5 剩余=各模块缺口之和
```

与自研服务 `/audit?format=text` 的输出逐字一致 —— 这是"插件自带内核、结果可复现"的直接证据。

已登记的工具 provider id 为 `coursepath/course_audit/course_audit`；工具名 `credit_audit`、`prereq_check`。

## 5. 四个坑（都踩过）

1. **签名校验**：Dify 1.17.1 默认 `FORCE_VERIFYING_SIGNATURE=true`，上传自打包会报
   `plugin verification has been enabled, and the plugin you want to install has a bad signature`。
   自托管做本地验证时在 `.env` 里设为 `false` 并 `docker compose up -d api worker plugin_daemon`。
   （提交市场**不需要**：市场侧用官方密钥签名。）

2. **uv 缓存在 Windows 绑定挂载上装不了依赖**：
   `failed to rename file ... /.uv-cache/.tmpXXXX -> .../archive-v0/...: Permission denied (os error 13)`。
   根因是 9p/drvfs 不支持 uv 的原子重命名。解决：给 `plugin_daemon` 加
   `UV_CACHE_DIR=/tmp/uv-cache`、`HOME=/tmp`（见 `deploy/dify.override.yaml`），安装目录仍在卷里可持久化。

3. **`tools/*.yaml` 的 `description` 必须在顶层**，缩进到 `identity` 下会报
   `Error loading tool configuration: 'description'`（`identity` 只认 author/name/label）。

4. **控制台 API 的 GET 也要 CSRF 头**：只给 POST 加 `X-CSRF-Token` 时，
   `plugin/list` 返回 `401 {"code":"unauthorized","message":"CSRF token is missing or invalid."}`。

## 7. 维护约定

- 改动 `campus-kb/core/{schema,graph,scoring}.py` 时，**必须**把改动同步到 `dify-plugin/course-audit/core/`，并在两处跑各自测试。
- 插件版本号与内核语义绑定：结论口径（R1–R5）变化时升 minor 版本。
- 插件不引入网络调用：一旦需要外部数据，应通过 `plan_json` 参数由调用方传入，保持 Low risk 与可审核性。
